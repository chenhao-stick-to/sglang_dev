Design Contract · 设计契约

核心设计原则

以下五条是 DSV4 HiCache + Mooncake 的不可违背契约：内存容量、节点备份原子性、以及 L3 七池前缀一致性（exists / get / set 同源逻辑）。

①

Device SWA 比例不变 · Host 拥有全量页

GPU 仍按 swa_full_tokens_ratio 缩小 SWA；Host 按 FULL 前缀 token 跨度过配 SWA/STATE 槽位。

full_host_pages = device_full_pages × hicache_ratio
swa_host_pages = (full_host_pages × page_size) ÷ swa_page_size
保证 L2/L3 可覆盖与 FULL 等长的前缀页，而不改变 device 侧 ratio 策略。

→ hybrid_pool_assembler._deepseek_v4_num_host_pages

②

仅「FULL + SWA 同长同节点」才允许备份

write_backup / write_backup_storage 前：FULL.value 与 SWA.value 必须同时存在且 token 数相等。

SWA tombstone（仅 FULL、无 SWA device）→ write_backup_skip_incomplete_swa，不进 L2/L3。 七池 L3 还要求 registered 七池全部出现在 transfer 中，否则 skip_partial_dsv4。

→ unified_radix_cache.write_backup · write_backup_storage

③

每个可备份 Node 拥有完整 FULL + SWA（+ 七池 sidecar）

节点级原子性：一次 backup 把该节点上 FULL、SWA、C4/C128/STATE 对齐到同一 logical 页槽。

C4/C128 跟 KV anchor indices；STATE 跟 SWA indices。单节点内各池 host 页一一对应，避免「FULL 已 backup、SWA 缺页」的 L3 不一致。

→ SidecarPoolSpec.indices_from_pool · commit_hicache_transfer

④

L3 exists：七池取「最小可共用前缀」

batch_exists_v2 对 required 池（C4/C128/C4_INDEXER）与 SWA 窗口池分别算边界，final_pages = min(各池命中页)。

全前缀池必须 page 0…N 连续存在；SWA/state 在 [0, final_tokens) 窗口内每页独立 hash 也需齐全。输出 pool_token_ranges 供后续 get/set 裁剪。

→ mooncake_store.batch_exists_v2 · hybrid_cache_controller._storage_hit_query

⑤

L3 get / set：七池按 KV 页同步 · 快速失败

_io_dsv4_pools_grouped：同一 kv_page_idx 上七池一起 get/set；任一池该页失败 → 立即停止后续页。

Get：每页所有池的 component key 都 get 成功才算该 KV 页 OK。Set：exist 后缺 key 才 put，任一页任池失败则截断前缀。保证 Mooncake 与 radix 树「七池同前缀」契约。

→ mooncake_store._io_dsv4_pools_grouped · _batch_io_v2_dsv4_grouped

内存容量：Device 小 SWA · Host 全前缀页

L1 Device（策略不变）

FULL KV pages — 100% 基准

SWA pages — ≈ swa_full_tokens_ratio（如 50%）

Device 仍可能 SWA tombstone；radix 允许 FULL on GPU + SWA 仅 host。

L2 Host（过配以对齐 FULL 前缀）

FULL logical + C4/C128 host pages — full_host_pages

SWA + STATE host pages — swa_host_pages（与 FULL token 跨度对齐）

Host 可缓存比 GPU 同时容纳更长的 SWA 前缀（HiCache 分层预期行为）。

节点备份门控（L2 / L3 共用）

FULL.value ✓ + SWA.value ✓ + len(SWA) == len(FULL) → 允许 write_backup
SWA tombstone 或 缺 C4/STATE 池 → 跳过 L2/L3 backup

L3 七池一致性契约（Mooncake）

exists 定边界 → get/set 在同一批 KV 页上对 7 个池同步成功或快速截断。

C4 C4_INDEXER C128 SWA C4_STATE C4_INDEXER_STATE C128_STATE

绿色描边 = 同一 kv_page_idx 必须同时 OK

Phase A
batch_exists_v2

required 池 chained 前缀连续命中；window 池窗口内每页命中；final_pages = min(全部)

Phase B · Get
prefetch grouped get

对每个 kv_page_idx：七池 key+ptr 批量 get；任一池失败 → break，不拉后续页

Phase C · Set
backup grouped set

对每个 kv_page_idx：七池 batch exist+put；任一池失败 → break，已写页不回滚但前缀截断

⚡
快速失败（Fast-Fail）

_io_dsv4_pools_grouped 在 if not all(page_ok_by_plan.values()): break 处停止递增 kv_page_idx，避免「KV 页 k 上 C4 成功但 SWA 失败」的半套前缀进入 radix。

5. L2 write_backup（Device → Host）

触发：_inc_hit_count 达阈值，或 device leaf demote（write_back 策略）。

flowchart TD A[write_backup node] --> B{parent backuped?} B -->|否| X[skip write_backup_skip_parent] B -->|是| C{FULL.value 存在?} C -->|否| X2[skip incomplete_full] C -->|是| D{SWA len == FULL len?} D -->|否| X3[skip incomplete_swa tombstone] D -->|是| E[build PoolTransfer] E --> F[KV: device_indices = FULL.value] E --> G[SWA: device_indices = SWA.value] E --> H[sidecar: indices_from_pool KV/SWA] F --> I[HybridCacheController.write] G --> I H --> I I --> J[alloc KV host + SWA host + resolve sidecar] I --> K[async DMA backup_from_device_all_layer] K --> L[commit: 写 node.host_value] L --> M[writing_check → 可选 write_backup_storage]

各组件 backup 范围（单节点 atomic）

  • FULL + C4/C128/C4_INDEXER：仅当前节点（单 leaf backup），indices 等长
  • SWA + STATE：同节点 SWA indices；STATE 跟 SWA，不单独扫树
  • 前置条件：FULL 与 SWA 必须同 token 数，避免 SWA tombstone 节点进 L3
