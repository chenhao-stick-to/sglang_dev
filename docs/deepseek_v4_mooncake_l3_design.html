DeepSeekV4 Mooncake L3 Storage

This design makes Mooncake storage usable for DeepSeekV4 hybrid cache by separating full-prefix compressed KV data from SWA-window state data. The storage hit result now matches the radix tree validator: a returned prefix can become a valid host-backed best node.

Pool Semantics

Required Prefix Pools

c4 c4_indexer c128

These pools are part of the compressed KV prefix. Mooncake checks their longest common prefix and converts each pool boundary back to KV-page granularity. The final full-prefix candidate is the minimum across all required pools.

SWA Window Pools

swa c4_state c4_indexer_state c128_state

These pools only need to cover the tail window used by SWA validation. They are not full-prefix requirements, but the returned hit length is rolled back until the tail window exists in every available SWA-window pool.

Key Construction

Pool Class Key Rule Compatibility
Required prefix Build chained hashes at each host pool page size with get_hash_str(page_tokens, prior_hash). Read and exists use new keys first, then fall back to legacy expanded KV-page keys.
SWA window Build independent hashes at swa_page_size with get_hash_str(page_tokens, None). Read and exists also support legacy fallback. Writes only emit the new key form.
Token ids, the previous prefix hash, sliding-window size, and per-pool token ranges are carried through HiCacheStorageExtraInfo.extra_info. The Mooncake backend does not inspect radix tree state directly.

Exists Algorithm

1. Anchor Start from v1 KV storage when the anchor has payload. For DeepSeekV4's logical anchor, use all requested KV pages as the initial candidate.
2. Prefix Pools Query c4, c4_indexer, and c128 with chained per-pool keys. Take the longest common KV-page prefix.
3. SWA Window Query SWA-window pools. Walk the candidate prefix backward until the tail window has all required pages.
4. Publish Return kv_hit_pages only after both prefix and SWA-window checks pass. This length is safe to insert into the host radix tree.

Backup And Prefetch

  • batch_set_v2() writes required-prefix pools and SWA-window pools with the same key builder used for reads.
  • Backup completion for a logical DeepSeekV4 anchor is the minimum successful prefix across required pools.
  • SWA-window writes are best effort. A failed SWA state write does not shorten backup completion, but it will reduce future L3 hits.
  • Prefetch allocates SWA host slots only for the confirmed tail window, then sidecar state pools reuse those SWA indices.
  • The host radix tree splits the inserted FULL node when needed so only the tail node carries ComponentType.SWA.host_value.

Safety Properties

Risk Guard
Returning a host prefix that SWA cannot validate batch_exists_v2() rolls the candidate back until the tail window exists.
Reading stale legacy Mooncake entries Legacy fallback is read-only. New writes use only the new DSV4 key scheme.
Publishing failed SWA get results into the tree Logical-anchor prefetch requires SWA-window get success before marking tokens completed.
Changing non-DeepSeekV4 behavior The DSV4 policy is enabled only when DSV4 sidecar pools are registered.
