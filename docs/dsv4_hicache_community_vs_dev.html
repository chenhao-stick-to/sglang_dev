问题诊断: 自己版本 L2 SWA全量 → 内存/L3 膨胀 + 最终改进方案
❌ 自己版本的核心问题
• L2 层 SWA/State = Full 同等级全量存储
→ node 的 SWA value 永远不为 tombstone
→ 每个 node 存储完整的 sliding window tokens
• 内存膨胀: SWA 在 L2 占用 = Full 级别
→ deep 前缀树中 SWA tokens 大量重复存储
• L3 膨胀: 备份时必须备份完整 SWA
→ 所有 7 池数据量 = Full 级别 × 7
→ 远端存储成本大幅增加
✅ 改进方案: 回退 + 两项关键修改
• 回退: SWA/State → 社区版 TRAILING_PAGES 策略
→ 恢复 SWA tombstone 机制
→ L2 SWA 按需存储，内存节省
• 修改 1: Prefetch & Backup 数据同步 + 失败标记
→ 保留各池 hit 策略 (ALL_PAGES / TRAILING_PAGES)
→ 改为页组织传输 + 跨池同步
• 修改 2: SWA/State 独立哈希
→ 不参与链式哈希
→ hash = SHA256(token_ids) 直接计算
